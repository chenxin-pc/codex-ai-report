## Purpose

规范研报入库、投研分析和研报库前端体验的信息架构、业务文案与诊断内容展示方式，确保前端优先服务投研用户的理解、操作和复核效率，同时保留现有后端接口契约与诊断数据可追溯性。

## Requirements

### Requirement: 前端 MUST 使用投研业务化信息架构

前端页面 MUST 在不改变现有后端接口、请求参数和响应 DTO 的前提下，将研报入库、投研分析和研报库观测能力组织为面向投研用户的业务化信息架构。页面文案 MUST 优先使用用户可理解的业务语义，不应把接口字段名、降级原因枚举或处理阶段原始标识作为主要展示文本。

#### Scenario: 查看投研分析页面

- **GIVEN** 用户打开投研分析页面
- **WHEN** 页面展示问题输入、分析状态、结论和证据
- **THEN** 页面 MUST 使用业务化中文标题和状态文案
- **AND** 页面 MUST 保留现有推荐接口调用方式
- **AND** 页面 MUST 将技术字段转译为可理解的提示

#### Scenario: 查看研报入库页面

- **GIVEN** 用户打开研报入库页面
- **WHEN** 页面展示文件选择、基础信息、标签和任务状态
- **THEN** 页面 MUST 按入库工作流组织表单和状态区域
- **AND** 页面 MUST 不新增后端必填参数
- **AND** 页面 MUST 保留现有上传接口契约

### Requirement: 证据与诊断内容 MUST 渐进展示

前端页面 MUST 默认降低长文本和工程诊断噪音。推荐证据、OCR 文本、切片对照和导入链路诊断 MUST 以摘要优先、按需展开的方式展示，避免默认铺开大段 `chunkText`、OCR 原文或 diagnostics。

#### Scenario: 查看推荐证据列表

- **GIVEN** 推荐接口返回多个证据片段
- **WHEN** 用户查看分析结果
- **THEN** 页面 MUST 默认展示证据摘要、来源、章节和可信度提示
- **AND** 页面 MUST 支持按需查看完整证据文本
- **AND** 页面 MUST 避免长文本遮挡分析结论

#### Scenario: 查看研报库诊断

- **GIVEN** 用户在研报库选择一篇报告
- **WHEN** 用户查看处理链路或切片对照
- **THEN** 页面 MUST 默认展示报告摘要和阶段状态
- **AND** 页面 MUST 将 OCR、切片和向量阶段明细放在可展开诊断区域
- **AND** 页面 MUST 保留现有观测接口的数据可追溯性
