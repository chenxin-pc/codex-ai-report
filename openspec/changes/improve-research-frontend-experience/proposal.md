## Why

当前前端页面已经覆盖研报入库、投研问题分析、研报观测和导入诊断，但信息组织更接近工程调试台：技术链路和原始字段展示较多，投研用户需要的分析主线、证据可信度、研报库管理和任务状态不够突出。

本变更希望在不调整后端接口、数据契约和业务逻辑的前提下，重新组织前端页面与交互，让现有能力以更贴近投研分析工作的方式呈现。

## What Changes

- 将主导航和页面文案从工程流程语义调整为投研业务语义，例如“研报入库 / 投研分析 / 研报库”。
- 重组研报入库页，将文件选择、基础信息、投研标签和入库任务状态分区展示。
- 优化投研分析页，将问题输入、快捷问题、分析状态、分析结论、证据质量和证据列表分层呈现。
- 将现有推荐流中的意图、输出等级、降级原因和证据质量字段转译为中文业务提示，避免直接暴露工程字段名。
- 优化证据列表展示，默认降低长文本噪音，并支持按需查看完整证据片段。
- 将研报观测页重组为研报库体验：默认展示研报列表和选中研报摘要，处理链路与切片对照改为按需展开的诊断区域。
- 将 OCR、切片、向量等阶段状态以标签化方式展示，提升列表和任务状态的可读性。
- 保留现有前端请求接口和参数，不新增后端 API、不修改 DTO、不改变入库、检索、推荐和诊断逻辑。

## Capabilities

### New Capabilities

- `research-frontend-experience`: 覆盖投研分析系统前端页面信息架构、业务化文案、分析结果展示、研报库诊断降噪和阶段状态呈现。

### Modified Capabilities

- 无。

## Impact

- 影响前端代码：`frontend/src/App.vue`、`frontend/src/style.css`。
- 影响用户可见页面：研报入库、投研分析、研报库、处理链路和切片对照展示方式。
- 不影响后端接口、数据库结构、OpenSpec 既有后端能力、推荐流式协议和导入链路处理逻辑。
- 不新增外部前端依赖；如需复制结论等浏览器能力，应使用浏览器原生 API 并提供失败提示。
- 需要通过前端构建验证，并按项目要求在提交前执行 `mvn -q test` 与 `openspec validate --all --strict`。
