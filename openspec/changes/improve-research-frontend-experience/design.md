## Context

当前前端是一个以 `frontend/src/App.vue` 为主体的 Vue 单页应用，页面包含研报上传、推荐分析、研报观测、处理链路和切片前后对照。页面功能已经连通，但信息架构以系统处理流程为中心，投研用户在使用时需要从工程字段、长文本证据和链路诊断中自行提炼业务含义。

本变更只调整前端页面与交互体验，继续使用现有接口和响应字段。已有的 `add-developer-ingest-chain-explanation-view` 变更聚焦开发者导入链路解释，本变更不替代该方向，只将当前前端中面向普通投研用户的默认体验降噪。

## Goals / Non-Goals

**Goals:**

- 将主导航、页面标题和模块文案调整为投研业务语义。
- 在研报入库页通过分区布局降低表单认知负担，并用状态标签展示现有任务状态。
- 在投研分析页分离问题输入、快捷问题、分析状态、分析结论、证据质量和证据列表。
- 将推荐流返回的元数据转译为中文业务提示，减少工程字段直接暴露。
- 将研报库默认体验聚焦在研报列表和选中研报摘要，处理链路和切片对照改为按需展开。
- 保持页面在桌面与窄屏下可用，避免长文本、表格和按钮造成明显重叠或不可读。

**Non-Goals:**

- 不新增、删除或修改后端接口。
- 不修改请求参数、响应 DTO、数据库结构、入库流程、检索召回、推荐生成和诊断数据生成逻辑。
- 不新增前端路由、状态管理库或 UI 组件库。
- 不实现需要后端持久化的收藏、历史记录、导出记录或用户偏好。
- 不实现完整开发者导入链路解释视图；该能力由已有变更承接。

## Decisions

### 1. 继续保持单页应用结构，先在现有组件内重组视图

本次改动优先在 `App.vue` 内按现有 tab 结构重排模板、计算属性和本地状态，不引入路由或组件拆分作为前置条件。

原因是当前前端规模较小，主要问题是信息组织和交互层级，而不是组件边界失控。保持单页结构可以降低实现风险，并确保变更范围集中在前端体验。

备选方案是拆分多个 Vue 组件或引入路由。该方案更利于长期维护，但会扩大本次提案的结构性改动，暂不作为必要范围。

### 2. 使用前端映射层转译状态和元数据

OCR、切片、向量阶段状态、推荐意图、输出等级、降级原因和证据质量字段均通过前端 helper 或 computed 映射成中文业务提示。

原因是这些字段已经由现有接口返回，前端可以在不改变契约的情况下改善可读性。未知值必须保留原值或显示兜底文案，避免因后端枚举扩展导致页面空白。

### 3. 诊断信息默认收起，按用户动作展开

研报库默认展示研报列表、搜索条件、视图切换和选中研报摘要。处理链路与切片对照仍使用现有接口加载，但只在用户点击“查看处理链路”或“查看切片对照”后显示。

原因是处理链路和切片明细对开发诊断有价值，但会干扰投研用户浏览研报和判断入库状态。按需展开能兼顾业务使用和诊断能力。

### 4. 长文本证据采用摘要优先展示

推荐证据和切片文本默认展示摘要或限制高度，并提供展开完整内容的交互。完整内容仍保留在页面内，不改变数据来源。

原因是研报 chunk 和切片对照文本可能很长，默认铺开会压低结论和证据质量信息的优先级。摘要优先能让投研用户更快扫描证据来源和相关性。

### 5. 不新增外部依赖

本次样式和交互使用 Vue 内置能力、浏览器原生 API 和现有 CSS 完成。

原因是变更目标是体验重排，不需要引入 UI 库。新增依赖会增加构建、样式一致性和维护成本。

## Risks / Trade-offs

- [Risk] 在单个 `App.vue` 内继续增加模板和状态可能让文件更长。→ Mitigation：实现时按页面区域组织 state、computed 和 helper，避免无关重构；如果后续继续扩展，再单独提组件化变更。
- [Risk] 前端业务文案映射可能覆盖不全。→ Mitigation：所有映射函数必须有未知值兜底，保留原始值或显示“未知状态”。
- [Risk] 诊断信息收起后，开发者可能觉得入口变深。→ Mitigation：研报库选中摘要中保留明确诊断按钮，并在失败状态下突出处理链路入口。
- [Risk] 表格、证据长文本和按钮在窄屏下可能溢出。→ Mitigation：实现时为表格保留横向滚动或卡片视图，为按钮和文本设置响应式布局与换行策略。
- [Risk] 只改前端无法真正新增筛选、历史和收藏能力。→ Mitigation：提案明确不承诺后端能力，快捷问题、复制结论和显示重排仅作为本地交互增强。
