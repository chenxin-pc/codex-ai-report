## Why

批量采集研报、导入 10 篇后汇总 OCR/切片结果、再从数据库拉取数据分析搜索质量，更像离线评估与运营流程，不适合全部写入在线业务接口主链路。将导入、导出和分析做成脚本化流水线，可以降低业务代码复杂度，也便于快速迭代 OCR、切片和检索参数。

## What Changes

- 新增脚本化研报采集与导入流程：脚本从配置的网站或本地目录收集 10 篇研报，调用现有导入能力完成 OCR、切片、入库和向量化。
- 新增脚本化质量分析流程：导入完成后，脚本从 MySQL 拉取 OCR、chunk、报告元数据和搜索结果，整理为 Excel。
- 新增脚本化搜索评估流程：脚本按配置的 query 集合调用搜索/推荐接口或共享评估入口，并将输入和输出整理为 Excel。
- 在线业务代码仅提供必要的导入、查询、搜索能力和可追溯数据，不承载“每 10 篇自动导出”的批处理编排。
- 支持脚本运行参数、配置文件、输出目录、失败重试和可重复执行，方便本地、测试环境和后续定时任务使用。

## Capabilities

### New Capabilities

- `script-report-ingest`: 定义脚本化收集研报、批量导入和导入状态记录要求。
- `script-quality-export`: 定义脚本从数据库拉取 OCR、切片、搜索结果并导出 Excel 的要求。
- `script-search-evaluation`: 定义脚本化执行搜索评估 query、整理推荐输入输出和人工评估字段的要求。

### Modified Capabilities

- 无。当前 `openspec/specs` 下尚无既有能力规格，本次以新增能力规格描述脚本化流水线。

## Impact

- 影响脚本目录：新增批量采集、批量导入、质量导出、搜索评估相关脚本和配置样例。
- 影响服务层：业务服务应暴露脚本所需的数据查询或复用现有 Mapper/Service，但不把批处理导出职责塞入 Controller。
- 影响持久化：如果当前数据库缺少 OCR 原文、页级结果、chunk 诊断、搜索评估记录等可追溯数据，需要补充表结构并同步 `schema.sql`。
- 影响 Excel 生成：可由 Java 脚本、Maven 命令或独立 CLI 生成 Excel，输出目录和文件命名必须可配置。
- 影响配置：脚本需要网站来源、本地文件目录、API 地址、数据库连接、评估 query、输出目录等配置，严禁硬编码生产密钥。
- 外部依赖：可能依赖目标研报网站、现有后端 API、MySQL、Milvus、OCR/Qwen 配置和 Excel 生成库。
