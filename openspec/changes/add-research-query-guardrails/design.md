## Context

当前推荐链路会将任意输入直接送入 Milvus 召回和模型生成。对“你好”这类非投研输入，系统仍会召回弱相关研报片段，并在投研 prompt 约束下输出严肃的证据冲突分析。这说明问题不只在召回质量，也在任务入口和输出强度控制。

产品定位保持为“投研专用助手”，不扩展通用闲聊能力。系统需要支持宽松投研模式：明确个股问题可完整分析，行业或主题问题可降级为主题观察，非投研输入则短路引导。

## Goals / Non-Goals

**Goals:**

- 在推荐链路入口引入投研可分析性判定，避免非投研输入触发召回和模型生成。
- 支持宽松模式，将输入划分为直接分析、主题分析、不可分析。
- 在输出前进行证据质量与主体一致性判断，按 L0-L3 分级控制输出力度。
- 同步推荐和流式推荐共享同一套判定语义，避免两个接口行为漂移。
- 保持规则可解释，并为后续引入模型分类器预留扩展点。

**Non-Goals:**

- 不提供通用聊天、闲聊陪伴或非投研问答能力。
- 不在本变更中新增外部模型分类服务或新的第三方依赖。
- 不改变 Milvus 作为主召回链路的定位。
- 不在无有效证据时生成实质性投资结论。

## Decisions

### 1. 使用投研可分析性三态，而不是通用/投研二分

输入判定结果分为：

- `ANALYZE`: 标的明确或问题足以支持完整投研分析。
- `THEME_OBSERVE`: 有投研意图但标的未锚定，可做行业或主题观察。
- `REJECT`: 无投研意图或不可分析，例如“你好”“在吗”“谢谢”。

这样可以保留宽松体验，同时避免主题问题被过早拒绝。

### 2. 非投研输入在召回前短路

`REJECT` 必须在调用向量召回前返回固定引导语。这样可以减少无意义向量搜索，也避免弱相关证据被模型包装成严肃结论。

### 3. 输出分为 L0-L3，并由证据状态决定最终强度

输出等级定义为：

- `L0`: 非投研拒答，只返回短引导。
- `L1`: 信息不足或污染，只说明原因并请求补充信息。
- `L2`: 主题观察，允许行业/主题层分析，禁止个股推荐。
- `L3`: 完整分析，要求标的明确、证据一致、引用有效。

输出等级由输入判定和证据校验共同决定。即使输入是 `ANALYZE`，只要证据混杂或引用缺失，也必须降级。

### 4. 主体一致性是输出前的硬约束

证据中出现多标的、跨交易所、代码/公司名冲突、引用跨主体时，系统必须降级到 L1，不能合并为单一投研结论。这个约束直接针对当前“北部湾港、NL003、国大药房”混杂案例。

### 5. Prompt 负责表达降级规则，服务层负责决定降级状态

服务层应尽量产出结构化状态，例如输入类别、输出级别、降级原因、禁用推荐语句标记。Prompt 使用这些状态组织语言，但不能独自承担安全边界。

## Risks / Trade-offs

- 规则误判导致投研问题被拒绝 → 宽松模式下将含有行业、财务、估值、风险、公司、代码等信号的问题放入 `THEME_OBSERVE` 或 `ANALYZE`，减少误拒。
- 主题问题输出过强 → `THEME_OBSERVE` 固定映射到 L2，禁止买入、增持、目标价、仓位建议等表达。
- 证据主体识别不完整 → 初期可基于标题、代码、交易所、公司名、行业关键词和 metadata 做保守判断，低置信时降级到 L1。
- 同步与流式接口行为不一致 → 抽象共享的判定结果和降级语义，两个接口只负责不同响应形态。
- 过多拒答影响体验 → 拒答文案保持短、清楚、可操作，引导用户提供公司名、股票代码或行业/主题研究问题。
